# M6.1 — Vendor Variant & Image Workflow Redesign

Brings the vendor product editor + marketplace variant experience to a mature
e-commerce standard (Shopify/Amazon-style) while staying compatible with the
existing BMPL data model, approval flow, storefront, and checkout.

## Root causes fixed
1. **Marketplace title reverted to the base product name** — `ProductVariant` had
   **no display-name field**; the variant "name" was only a client-side option-value
   join and the detail H1/cart used `product.title`. → Added `ProductVariant.displayName`
   and a single title-precedence rule (`@bmpl/shared` `resolveVariantTitle`):
   `displayName → option-value label join → base product title`, applied in the public
   detail, cart, checkout snapshot, and order.
2. **Options locked after variants existed** — `deleteOption`/`deleteValue` required
   zero variants; the editor also hid "Add value" once variants existed. In fact
   `addValue` never required zero variants (it always worked server-side). → The editor
   now always exposes "+ Add value"; `deleteValue` removes the value **and** its
   dependent variants (order references preserved via `SetNull`), requiring `?force=true`
   confirmation only when those variants carry inventory or orders; renaming a value is a
   new endpoint that never recreates variants.
3. **No safe bulk variant generation** — variants were only created one-by-one. → New
   `POST variants/generate` creates **only the missing** option-value combinations,
   preserving every existing variant's id, images, price, SKU, inventory, display name,
   and order references (idempotent).
4. **Images weren't real per-variant galleries** — `ProductImage.variantId` existed but
   `isPrimary` was product-wide (one primary per product) and there was **no file
   replace**. → `confirm` now makes the first image in each variant group that group's
   primary; `setPrimary` is per-variant-group; `variantPrimaryUrls` powers variant-
   specific cart/order thumbnails; a new `POST images/:id/replace` swaps the file **in
   place** (preserving variant, position, primary, alt/caption); reassigning an image to
   another variant reconciles the per-group primary.
5. **Cart/order used the product image + base title** — cart lines now carry
   `variantTitle` and the variant's own image; the order snapshot stores the variant
   display name.

## Migration
`20260804120000_variant_display_name` — additive: `ALTER TABLE product_variants ADD
COLUMN "displayName" TEXT` (nullable). **No destructive backfill:** when `displayName`
is null the API falls back to the option-value label join, which reproduces every
existing variant's name exactly, so all existing products/variants keep working and no
marketplace URLs, carts, or orders break.

## API additions (all `/vendor/products/:productId`)
`POST variants/generate` · `PATCH option-values/:valueId` (rename) ·
`DELETE option-values/:valueId?force=` (remove value + variants w/ confirmation) ·
`displayName` on `POST variants` + `PATCH variants/:id` · `POST images/:id/replace`.
Public `variants[]` now include `title`, `displayName`, `optionLabel`; cart lines include
`variantTitle`; order items snapshot the variant display name.
